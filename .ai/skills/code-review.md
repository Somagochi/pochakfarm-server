# Code Review

우선순위는 `정합성 -> 보안 -> 설계 -> 테스트 -> 스타일` 순서다.

## 우선 확인 항목

### 1. 도메인 규칙 위치
- 비즈니스 규칙이 domain이 아니라 service나 controller에 새지 않았는가
- aggregate 경계를 무시한 직접 접근이 없는가
- repository가 aggregate root 기준으로 설계되었는가

### 2. 트랜잭션과 정합성
- 읽기-수정-쓰기 패턴에 경쟁 조건이 없는가
- 트랜잭션 경계가 application 계층에서 적절히 잡혔는가
- 여러 aggregate를 한 번에 무리하게 수정하지 않는가

### 3. 보안
- 인증/인가 누락이 없는가
- 민감 정보가 로그나 응답에 노출되지 않는가
- 입력 검증이 빠지지 않았는가

### 4. MySQL 관점
- N+1 또는 불필요한 전체 조회 가능성이 없는가
- 인덱스나 제약조건이 필요한 변경인데 빠지지 않았는가
- 스키마 변경 시 마이그레이션 고려가 되었는가

### 5. 테스트
- 동작 변경에 맞는 JUnit 5 테스트가 추가되었는가
- 정상 케이스와 실패 케이스가 모두 있는가
- 보안/인가 변경이면 관련 테스트가 있는가

### 6. 코드 품질
- 함수가 한 가지 책임만 가지는가
- 이름이 역할을 설명하는가
- Google Java Format과 기존 스타일을 깨지 않는가

## 출력 형식

```md
## 리뷰 결과

### Critical
- {파일}:{라인} - {문제}

### Warning
- {파일}:{라인} - {문제}

### Suggestion
- {파일}:{라인} - {제안}
```

## 주의사항

- 변경사항이 없으면 리뷰하지 않는다.
- 자동 생성 파일은 제외한다.
- 코드 리뷰만 요청된 경우 빌드나 테스트를 임의로 실행하지 않는다.
