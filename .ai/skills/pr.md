# PR

## 요청 구분

- `PR 준비해줘`: PR 제목과 본문 초안만 작성한다.
- `PR 올려줘`: PR 제목과 본문 작성 후 실제 PR 생성까지 진행한다.

## 기본 규칙

- 대상 브랜치는 기본적으로 `dev`다.
- 현재 브랜치가 `main` 또는 `dev`면 바로 PR을 만들지 않는다.
- PR 본문은 `.github/PULL_REQUEST_TEMPLATE.md`를 따른다.
- 스크린샷이 없으면 해당 섹션은 비워두거나 `없음`으로 정리한다.

## PR 작성 순서

1. 현재 브랜치 확인
2. 대상 브랜치 확인
3. 변경 파일과 커밋 내용 확인
4. 실행한 테스트 또는 검증 내용 확인
5. 템플릿 형식으로 PR 제목과 본문 작성
6. `PR 올려줘` 요청이면 실제 PR 생성

## 본문 작성 기준

### ✨ 작업 내용
- 무엇을 추가하거나 변경했는지 요약
- 리뷰어가 봐야 할 핵심 포인트

### 📸 스크린샷 / 참고 자료
- 스크린샷이 없으면 `- 없음`

### 📝 리뷰어 참고사항
- 리뷰 시 같이 봐야 할 포인트가 있으면 적는다.
- 이번 PR에서 의도적으로 하지 않은 것이 있으면 적는다.
- 없으면 `- 없음`

## 제목 작성 기준

- 브랜치명과 변경 목적이 드러나게 작성한다.
- 문서 작업이면 `docs:` 성격이 드러나게 작성한다.

## 완료 기준

- 제목과 본문이 템플릿에 맞다.
- 변경 내용과 검증 내용이 빠지지 않았다.
- `PR 올려줘` 요청이면 PR URL까지 확인한다.
