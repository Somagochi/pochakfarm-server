# Spec

기능 구현 전에 요구사항, 범위, 도메인 경계를 먼저 정리한다.

## 포함할 내용

### 1. 작업 요약
- 무엇을 위한 기능인지
- 누가 사용하는지
- 기대 결과가 무엇인지

### 2. 범위
- 이번 작업에 포함되는 것
- 이번 작업에서 제외되는 것

### 3. 도메인 관점 정리
- 관련 bounded context
- 관련 aggregate root
- 새로 생기는 entity / value object / policy가 있는지
- 비즈니스 규칙이 어디에 들어가야 하는지

### 4. 입출력 관점
- API 또는 내부 유스케이스 입력
- 성공 결과
- 실패 조건과 예외 상황

### 5. 데이터 영향
- MySQL 테이블 변경 여부
- 인덱스, 제약조건, 마이그레이션 필요 여부

### 6. 테스트 관점
- 꼭 검증해야 하는 정상 케이스
- 꼭 검증해야 하는 실패 케이스

## 권장 템플릿

```md
# {작업명} Spec

## 작업 요약
- 목적:
- 사용자/주체:
- 기대 결과:

## 범위
- 포함:
- 제외:

## 도메인
- bounded context:
- aggregate:
- 핵심 규칙:

## 입출력
- 입력:
- 성공 결과:
- 실패 조건:

## 데이터 영향
- MySQL 변경:
- 마이그레이션:

## 테스트 포인트
- 정상 케이스:
- 실패 케이스:
```

## 완료 기준

- 모호한 부분이 없다.
- 도메인과 aggregate가 드러난다.
- 구현 전에 필요한 질문이 정리되어 있다.
