# Test Guide

이 프로젝트의 테스트는 JUnit 5를 기본으로 한다.

## 어떤 테스트를 작성할지

### Domain / Application
- 비즈니스 규칙
- 예외 조건
- 상태 전이
- 트랜잭션 경계에서 기대하는 동작

### Presentation
- 요청 검증
- 응답 상태 코드
- 인증/인가
- 요청/응답 스키마

### Infrastructure
- 복잡한 쿼리
- MySQL 매핑
- 외부 연동이 핵심인 경우의 통합 동작

## 권장 스타일

- 테스트 이름은 한글 또는 의도가 분명한 영어로 작성한다.
- given / when / then 흐름이 드러나게 작성한다.
- 하나의 테스트는 하나의 핵심 행동을 검증한다.

## 체크리스트

- JUnit 5 기반인가
- 정상 케이스가 있는가
- 실패 케이스가 있는가
- 경계값이 필요한가
- 보안 관련 변경이면 인증/인가 테스트가 있는가
- DB 변경이면 MySQL 기준으로 검증이 필요한가

## 실행 명령

- 전체 테스트: `./gradlew test`
- 전체 검증: `./gradlew check`

## 주의사항

- 동작 변경이 있으면 테스트도 함께 수정하거나 추가한다.
- flaky test를 만들지 않는다.
- 외부 환경에 의존하는 테스트는 목적이 분명할 때만 추가한다.
